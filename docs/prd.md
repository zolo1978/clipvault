# PRD — ClipVault

> 本地剪贴板历史管理器。自动记录、快速搜索、一键粘贴。
> 评审检查清单见 SKILL.md Section 6。

## 1. 背景

开发者与知识工作者日均复制粘贴操作超过 **200 次**（JetBrains 2024 Dev Survey），频繁跨应用切换上下文。现有方案存在明显差距：

- **macOS 原生**仅保留最近 1 条剪贴板，无法回溯。
- **Maccy / CopyClip** 仅支持 macOS，不支持图片和文件路径的统一管理。
- **Ditto**（Windows 开源）UI 陈旧，搜索性能在记录超过 5000 条时明显退化。
- **1Password / Paste** 等商业化产品需要订阅（$15–$30/月），且数据经云同步，存在隐私顾虑。

机会窗口：**原生性能 + 离线优先 + 跨平台（macOS + Windows）+ 零订阅**，基于 Tauri v2 实现 Rust 后端的高效剪贴板监控与 SQLite 本地存储。

## 2. 目标用户

- **主要用户**：软件开发者 / 内容创作者，20–45 岁，日均处理 200+ 次复制粘贴，频繁在 IDE、浏览器、终端、文档之间切换。桌面高频使用（每日 8h+）。
- **次要用户**：办公室白领（财务、法务），需要频繁复制模板文本、表格片段。
- **桌面端场景**：长时间工作会话中快速检索历史剪贴板内容并粘贴到目标应用。
- **移动端场景**：V1.0 不涉及。

## 4. 离线策略

ClipVault 为纯本地应用，所有功能零网络依赖。

| 功能 | 离线级别 | 说明 |
|------|---------|------|
| 剪贴板监控与记录 | 必须离线 | 本地 SQLite 存储，无网络交互 |
| 搜索历史记录 | 必须离线 | 本地全文搜索，SQLite FTS5 |
| 全局快捷键 | 必须离线 | 系统级热键注册，无需网络 |
| 收藏/置顶 | 必须离线 | 本地数据库标记 |
| 导出/导入 | 必须离线 | 本地文件系统读写 |
| 自动更新检查 | 仅在线可用 | 联网时检查 GitHub Releases，离线时静默跳过 |

## 5. 平台差异

| 功能 | macOS | Windows | 说明 |
|------|-------|---------|------|
| 剪贴板监控 | P0 | P0 | macOS: NSPasteboard 监听 / Windows: Win32 clipboard listener |
| 全局快捷键 | P0 (Cmd+Shift+V) | P0 (Ctrl+Shift+V) | 平台差异通过 Tauri 插件抽象 |
| 系统托盘 | P0 | P0 | Tauri tray 插件统一 API |
| 开机自启 | P1 (LaunchAgent) | P1 (注册表) | 实现路径不同 |
| 暗色模式 | P1 | P1 | macOS: NSAppearance / Windows: system theme event |
| 文件路径记录 | P0 | P0 | macOS: file URL scheme / Windows: file drop format |

> V1.0 仅支持 macOS + Windows。Linux 作为 P2 推迟到 V1.1。

## 7. 性能指标

| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 冷启动 | < 500ms | 双击图标到托盘图标出现，Release build，本地 profiling |
| 热启动（唤起面板） | < 150ms | 按快捷键到面板可见，Release build |
| 内存占用（空闲） | < 40MB | 托盘后台运行 1h 后 Activity Monitor / Task Manager RSS |
| 内存占用（10000 条记录） | < 80MB | 记录 10000 条后托盘状态 RSS |
| IPC 延迟 | < 5ms P99 | 前端 → Rust 单次 invoke（搜索请求） |
| 搜索响应 | < 100ms / 1000 条 | SQLite FTS5 查询耗时，前端计时 |
| 搜索响应 | < 300ms / 10000 条 | 同上 |
| 安装包体积 | < 10MB | macOS .dmg / Windows .msi 未压缩大小 |
| 剪贴板监控 CPU | < 1% | 后台监控 1h 平均 CPU（Activity Monitor） |
| 数据库写入 | < 50ms P95 | 单条剪贴板记录写入 SQLite 耗时 |

## 8. 技术约束

- **Rust**: 1.80+ MSRV，CI 中 enforced via `rust-toolchain.toml`
- **Tauri**: v2.x，前端 `@tauri-apps/api` v2
- **前端**: React 19 + TypeScript 5.x + Vite 6 + Tailwind CSS 4 + Zustand 状态管理
- **UI 组件**: shadcn/ui（Radix 基础）
- **最低系统**: macOS 13 (Ventura) / Windows 10 21H2+
- **存储**: 本地 SQLite（via `rusqlite` bundled），FTS5 全文搜索
- **剪贴板访问**: macOS — `cocoa` / `objc` crate；Windows — `windows-rs` Win32 API
- **分发**: macOS DMG + 代码签名 / Windows NSIS installer
- **CI**: GitHub Actions — lint → test → build → release

## 8.5. 安全与隐私

- **数据收集**: 零。应用不收集任何用户数据，无遥测、无分析、无崩溃上报。
- **本地存储**: 剪贴板数据存储在用户 AppData/Library 目录下 SQLite 文件中，无加密（用户可选启用 OS 级全盘加密）。
- **网络传输**: V1.0 无任何网络请求。自动更新检查为唯一可选联网功能（HTTPS to GitHub Releases API）。
- **权限声明**: Tauri Capabilities 最小权限集：
  - `clipboard-read`：读取系统剪贴板
  - `global-shortcut`：注册全局热键
  - `tray`：系统托盘
  - `fs-read`：仅应用数据目录
  - `fs-write`：仅应用数据目录
- **合规**: 无网络数据传输，不涉及 GDPR/CCPA 数据主体权利。macOS App Sandbox 兼容。
- **敏感内容处理**: 用户可在设置中配置排除列表（如 1Password 等密码管理器的剪贴板内容自动跳过）。

## 11. 用户故事（P0）

### US-1: 剪贴板自动记录

```
As a 开发者,
I want 系统自动记录我复制的每一段文本/图片/文件路径，
so that 我可以在需要时回溯任何之前复制过的内容。

AC1: 复制一段文本后，在 ClipVault 面板中 100ms 内可见新记录。
AC2: 连续复制相同内容 5 次，仅产生 1 条记录（hash 去重）。
AC3: 截图复制后（PNG），面板显示缩略图预览。
AC4: 数据库已存储 10000 条记录，新内容写入延迟 < 50ms。
```

### US-2: 快捷键搜索并粘贴

```
As a 开发者,
I want 通过 Cmd+Shift+V 快速唤起搜索面板，输入关键词定位历史记录并粘贴到当前应用，
so that 我无需离开键盘即可完成跨应用内容复用。

AC1: 在 VS Code 中按 Cmd+Shift+V，面板在 150ms 内弹出。
AC2: 输入 "docker" 后 100ms 内返回匹配结果（1000 条记录内）。
AC3: 选中一条记录按 Enter，内容粘贴到 VS Code 光标位置，面板自动关闭。
AC4: 粘贴完成后，系统剪贴板恢复为粘贴前的内容。
```

### US-3: 托盘常驻无感运行

```
As a 开发者,
I want ClipVault 启动后静默运行在系统托盘中，
so that 它不占用 Dock 栏/任务栏位置，但随时可用。

AC1: 启动后仅在系统托盘显示图标，无主窗口弹出。
AC2: 右键托盘图标显示菜单：显示面板 / 暂停监控 / 设置 / 退出。
AC3: 点击「暂停监控」后停止记录，图标变为灰色标识暂停状态。
AC4: 关闭主窗口（Cmd+W）不退出应用，仅隐藏窗口。
```
